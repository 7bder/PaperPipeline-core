# Elsevier 编号制口径（逐条经真实 Elsevier 定稿验证；合稿脚本为各项目工具目录内的 72 号生产脚本，命名两制、按需在项目内生成）

本碎片只管**引用与文献表的写法**。跨出版社共性条款在 `md-single-source.md`，图件与数据披露在
`lab-experimental-reporting.md`。换刊 = 改领域档的 `fragments:` 声明，不改脚本。

1. 正文引用一律写成半角方括号数字 `[n]`，置于被支持句末、句点之前。出处定稿
   `30-manuscript/36-draft.md` 实测 53 处引用标记（46 个不同形态）**全部**是该形：
   无 `Ref. [n]`、无上标 `^[n]`、无作者-年份制。机检：`scripts/45-consistency-check.py` 判据①。
2. 一条括号内并列多个编号用逗号分隔、**逗号后不加空格**：`[11,14]`、`[1,5,17,22]`。
   区间合并写法 `[1-3]` 本项目未使用（实测 0 处）；45 号脚本容忍它但不生成它。
   要用区间先在此处补口径，别在正文里临时起意——同稿混用两种并列法会被人工评审记为格式不一致。
3. 文献表条目格式固定为 `[n] 作者. 标题. 期刊, 年. DOI: <doi>`（模板见合稿脚本的 `ref_lines`）：
   作者串与标题**先去掉末尾句点**再拼接；DOI 每条必列（出处定稿实测 49 条 / 49 条含 DOI）。
   行首必须是 `[n]`——45 号脚本按行首 `[n]` 认条目行，写成 `- [1] …` 或 `\bibitem{}` 会让判据①
   找不到任何条目（该情形脚本返 rc=2，不会静默判绿）。
4. **允许跳号，且跳号不是缺陷**：文献表只列被引条目，编号沿用文献库（`20-lit/22-refs.json`）原编号，
   故实际编号呈 `[1] [5] [7] [11] [14] …` 形态（出处定稿实测例）。任何"参考文献编号须从 1 连续"的检查都是误检，不得添加。
   代价是投稿前须由生成器或人工重排为连续号——这一条属排版阶段，不属真源阶段。
5. 作者串是文献库的原样（`;` 分隔、可含 `et al.`），且库中**无 volume / issue / 页码**三个字段。
   因此这三项在真源里必然缺失，属**已知缺口而非风格选择**：定稿前须逐条补全，作者串须转成目标刊
   要求的形态（模板 `cas-model2-names.bst` 会按刊印形态重排，但补全后的字段须回到文献库，
   真源与库不得分叉）。缺口不得靠删除条目来"消除"。
6. LaTeX 侧**不用** `thebibliography` / `\bibitem` 手写文献表：走
   `60-latex/templates/els-cas-templates/` 的 `cas-sc.cls`，
   `\bibliographystyle{cas-model2-names}` + `\bibliography{refs}`，tex 内引用写 `\citep{<bibkey>}`
   （BibTeX key，不是数字）。
7. 由第 6 条得一条硬约束：**md 里的 `[n]` 与 PDF 里印出的编号不是同一套**——`.bst` 按 `\cite`
   首次出现顺序重新编号。所以"引用 ↔ 文献表一一对应"只在 md 真源层判（45 号脚本），
   PDF 层只验页数、图数与引用标记无残留（`72-latex-build-check.py`）。
   不得拿 PDF 的编号去反查 md 的编号，那是一次注定失败的比对。
8. 投稿要件：Highlights **有**——3–5 条，每条不超过 85 字符（出处定稿 `task-finalize-manuscript`
   验收口径原文，且 `verify_manifest` 对定稿产物断言含 `Highlights` 键词）。
   Graphical abstract 出处定稿**未采用**（评审报告的投稿要件缺口清单里也没有它）；
   目标刊若要求，在领域档另起一个碎片声明，不写进本碎片。
