# claim 框架与引用落位（P2 定义，P4 执行）

> **阶段定位**：本文件是**顺序上的前段**。P2 产出 `20-lit/20-claims-map.md`（= 对文献的**需求单**），
> P3 的检索（见 `30-literature-pipeline.md`）按这张单子定向采购，P4 写作时按本文件的落位规则把引用钉进句子。
> **顺序不可颠倒**：先需求单、后采购、再落位。

## 1. 为什么顺序必须是 idea → 框架 → 文献 → 撰写

颠倒顺序会得两种病（本项目实测各中一次）：

| 病 | 症状 | 根因 |
|---|---|---|
| **库存病** | 库很大但用不上：thesis 库 74 条，实际只引 49 条，**25 条成为未引库存** | 检索期没有需求单 → 按"话题相关"广检，而不是按"claim 需要什么证据"定向取 |
| **临时凑引病** | 写作期才发现某句没人支撑 → 临时找文献 → over-claim、引用落位失控 | 框架期没把 claim 与证据类型绑死 |

因此规定：**任何文献检索任务的输入必须是 claims_map 的待补需求行，禁止"尽可能多检"**；检索产出的库只对"被需求单引用"的条目负责。

## 2. claims_map（P2 产物，唯一路线图）

`20-lit/20-claims-map.md`，每行一条 claim。**先建骨架（文献列可空），再在 P3 回填**：

| 字段 | 说明 | 机检 |
|---|---|---|
| `claim_id` | C-1… | 唯一 |
| `text` | 断言句，**与正文逐字一致** | 与正文比对 |
| `role` | 背景 / 机制 / 分歧 / 缺口 / 本文贡献 | 枚举 |
| `needs` | 需要的证据类型（如"SiO2 壳抑制光催化的先例"） | 非空 = 待采购 |
| `refs` | 支撑 ref_no（P3 回填） | 见 §3 门限 |
| `evidence_strength` | `direct-data` / `full-text` / `title-abstract` / `unsupported` | 枚举，禁 unsupported 入骨架 |
| `boundary` | 不能说到什么程度 | 非空（机制/因果类必填） |
| `section` | 落点（Intro / 3.x / Discussion） | 位置-职责匹配 |

## 3. 证据强度门限（分层，非一刀切）

| 类型 | 门限 | 违反时 |
|---|---|---|
| 所有 claim | ≥1 条支撑文献**或** `direct-data`（本稿数据直证） | 不允许进骨架 |
| 机制 / 因果 | ≥1 条 **A 级全文核对** | 必须降级标注"机制表述引文献，非本稿直证" |
| 背景 / 现状 | 允许题录+摘要级 | 不得据其推定量结论 |
| 分歧 / 争议 | ≥2 条立场相反文献 | 视为伪分歧，删或补 |
| 新颖性（首次/与 [x] 不同） | ≥1 条全文核对 + 1 条对比基线 | 禁用"首次"除非附检索覆盖声明 |

领域加严由 `profiles/*.yaml` 注入（临床/社科：效应量与 CI 的原文页级；CS/ML：baseline 原文 + 复现性声明；理论：引理依赖完整）。

## 4. 段落结构（四步，禁止文献罗列段）

**共识 → 分歧 → 缺口 → 本文位置**。每一步都必须落到 claim 行；不允许出现"只堆文献不给论断"的段落。
每节写完做**反向大纲**：提炼"论点句 → 证据"，**映射不上的段落删除**，不保留。

## 5. 引用落位机检 5 条（P4 执行，合稿/审计时复跑）

1. **句级引用 ⊆ 该句 claim 行的 `refs`**；
2. **孤儿引用 = 0**（正文引用但不在任何 claim 行 → 报错）；
3. **孤儿 claim = 0**（claim 行未被任何句子引用 → 报错，或显式标"背景性，不落正文"）；
4. **位置-职责匹配**：背景类只入 Introduction，机制/对比类只入 Discussion，数据类必须回指 `data/` 源；
5. **数字断言可复算**：任何带单位的数值必须能在数据源中复算。

## 6. 不支持的处置（三选一，必留痕）

**替换文献 / 降级措辞（hedging，部分支持必须收窄）/ 删除断言**——三者逐条记录在引用审计文件中。
实例：`a gradient of crosslinking` → `a curing gradient …, an effect that oxygen inhibition reinforces`（依据 #15 全文 p4 + #90 p12）。

## 7. Title / Keywords 写作指引

> **软约束：指引性，不进 verify manifest，不阻断 done**（用户裁决 2026-10-06：质量层一律软约束，
> 由 P4 阶段必读与本文件的语义审查生效，不设机检 FAIL）。

### 7.1 Title

- **陈述式标题**：标题应陈述发现或对象（"X enables Y under Z"），不用纯方法罗列式，也不用问句式（综述/观点类除外）。
- **长度上限**：≤ 20 词（或按目标期刊 Author Guide 更严上限收窄）；超长优先砍修饰语，不砍限定条件——**适用条件（温度、体系、浓度窗口）宁短勿丢**，丢限定即标题层 over-claim。
- **禁未定义缩写**：标题不使用本稿自定义缩写（如试样代号）；领域通用缩写可用，但拿不准是否通用时一律展开。
- **与 claims_map 对齐**：标题承载的核心断言必须能在 claims_map 找到对应 claim 行，且其 `evidence_strength` 达到 §3 门限——标题是全文最强的 claim，适用最强的证据要求。

### 7.2 Keywords

- **数量 5-7 个**（多数期刊硬限 6，取交集按目标期刊收窄）。
- **缩写一律展开**：关键词是检索入口，写全称（必要时"全称（缩写）"并列），不写只有本稿才懂的代号。
- **不逐字复读标题词**：补足标题未覆盖的检索面（体系、方法类别、性能维度各占一席）。
- **由宽到窄排序**：领域词在前、本稿特指词在后，方便检索系统加权。

## 8. Discussion 结构模板与独立 Limitations

> **软约束：指引性，不进 verify manifest，不阻断 done**（同 §7 头部裁决口径）。

### 8.1 Discussion 四步模板

按序展开，每步都必须落到 claims_map 的 claim 行（与 §4 段落结构、反向大纲同口径）：

1. **重述发现（Findings）**：首段一句话重述核心发现，措辞与 claims_map 中 role=本文贡献 的 claim 行**逐字一致**（§2 字段表 `text` 列的要求），不换说法、不加程度词。
2. **对照最强对手（Strongest prior）**：与**最接近、最具威胁性**的已有工作逐项对比（数据、条件、适用域三口径），不对弱对手取胜式对比；此处的新颖性表述受 §3 门限约束（≥1 条全文核对 + 1 条对比基线，否则禁用"首次"）。
3. **机理（Mechanism）**：机理解释逐句执行 §3 的 A 级全文核对门限；本稿数据不能直证的机制句必须带降级标注（"mechanistic interpretation drawn from ref. [x], not directly evidenced here"），并回指该 claim 行的 `boundary`。
4. **意义（Implications）**：分两层写——本研究的直接意义（boundary 内）与领域外推（boundary 外，须显式标注为外推/展望）；**外推层禁止使用结论级措辞**（significant impact、universal 之类），与 §6 hedging 口径一致。

### 8.2 独立 Limitations 写法

- **独立成节**，不埋在 Discussion 末段（审稿人按节检索，独立节是对审稿成本的直接尊重）。
- **逐条回指 claims_map 的 `boundary` 字段**（§2 字段表）：每条 limitation 对应至少一行 claim 的 `boundary`——boundary 写"不能说到什么程度"，Limitations 写"哪些没做到、为什么"；两者措辞不必逐字相同，但**指向必须能对上**（按 claim_id 引用）。
- **每条三要素**：① 限制陈述（缺什么：对照、样本量、时间窗、条件域）② 影响范围（哪些 claim 因此只能收窄到什么程度）③ 后续可补性（能补→写补法；不能补→写明是设计约束而非疏漏）。禁写空洞的 "future work will investigate…" 收尾句。
- **与 §5 落位机检的关系**：Limitations 节本身不进 5 条机检（机检管引用落位），但其中引用的数字断言仍受 §5 第 5 条（可复算）约束——Limitations 不是数字断言的法外之地。
